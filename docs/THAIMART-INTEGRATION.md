# Thaimart import — 26 กันยายน 2026

## วิธีใช้งาน

สินค้า → นำเข้าจาก URL → วาง URL หรือข้อความแชร์ → อ่านข้อมูล → ตรวจชื่อ ราคา รายละเอียด รูป และตัวเลือก → ยืนยันบันทึก (ค่าเริ่มต้นเป็นฉบับร่าง)

สินค้าเดิมเปิดแก้ไขแล้วกด “อ่านลิงก์” ได้ การอ่านใหม่ยังไม่เปลี่ยนฐานข้อมูลจนยืนยัน รูปสินค้าและรูปในรายละเอียดถูกคัดลอกเข้า R2 ตอนบันทึก ร้านเพิ่ม ลบ จัดรูปปก แก้ alt text และผูกรูปกับตัวเลือกได้

## ข้อมูลต้นทางที่ตรวจแล้ว

อ่าน HTML สาธารณะผ่าน HTTPS ปกติได้โดยไม่ล็อกอิน ไม่ใช้ API ภายใน ไม่รันสคริปต์ ไม่หลบระบบป้องกัน:

| Product ID | Gallery รวมรูปตัวเลือกไม่ซ้ำ | ตัวเลือก | รูปในรายละเอียด |
|---|---:|---:|---:|
| 6a8489fba9ceed89ab290994 | 9 | 3 | 6 |
| 6a9a93282705a45c43210118 | 7 | 5 | 0 |
| 6a4f1ddcc9e4f296dd94a3e3 | 5 | 2 | 0 |

Adapter อ่าน JSON จาก React Flight และ text records ที่ระบุความยาว UTF-8 รวมทั้งรองรับ Product JSON-LD ถ้ามี ใช้ product ID ตรงกับ URL ไม่มี AI สร้างข้อมูลแทนส่วนที่ขาด

## ขอบเขตและข้อจำกัด

- อนุญาต product URLs ของ thaimart.com และรูป HTTPS จาก img-cdn.thaimart.com เท่านั้น ไม่ตาม redirect
- ชื่อ ราคา รายละเอียด หมวดหมู่ แกลเลอรี คุณลักษณะ SKU รูปตัวเลือก น้ำหนัก ขนาด และสถานะพร้อมขายเป็น snapshot ณ เวลานำเข้า
- รูปไม่เกิน 40 รูปแกลเลอรี/5 MB ต่อไฟล์ ตัวเลือกไม่เกิน 100 แบบ HTML รายละเอียดไม่เกิน 100,000 ตัวอักษร ข้อมูลเกินขีดจำกัดแจ้งข้อผิดพลาด ไม่ตัดรูปทิ้งเงียบ ๆ
- หน่วยน้ำหนัก/ขนาดต้องตรวจต้นทางก่อนยืนยัน ไม่เดาหน่วยที่ข้อมูลไม่ได้ระบุ
- รักษาย่อหน้า หัวข้อ รายการ ตัวหนา/เอียง อีโมจิ และรูป ลบ script และ HTML ที่ไม่ปลอดภัย; iframe รองรับเฉพาะ YouTube ที่ร้านเพิ่มเอง
- วิดีโอต้นทางยังไม่นำเข้า จะแสดงคำเตือนเมื่อพบ; ร้านแทรก YouTube หรืออัปโหลด MP4 เองในรายละเอียดได้ ไม่มี price/stock sync และการเลือกแบบเพื่อสั่งซื้อทำที่ Thaimart
- รายละเอียดทั้งหมดอยู่ใน HTML ของหน้าร้านหน้าเดียว มี canonical/meta/JSON-LD Product + Offers; staging ใช้ noindex
- การลบรูปจากสินค้าทำให้เลิกแสดง แต่ยังไม่มีงานเก็บกวาดไฟล์ R2 ที่ไม่ถูกใช้งาน
- หากต้นทางเปลี่ยนโครงสร้างหรือไม่อนุญาตให้อ่าน ระบบแจ้งข้อผิดพลาดและให้กรอกเอง

## การตรวจสอบ

Automated tests ครอบคลุม UTF-8 Flight parsing, sanitization, สิทธิ์รูปข้ามบัญชี, private/published media, variants/price, การคงข้อมูลเดิม และ SSR structured data; ตรวจ bundle ด้วย Wrangler dry-run ด้วย

ตรวจ staging จริงหลัง deploy: ล็อกอินและ /api/import ทั้ง 3 URLs ผ่าน ได้รูป/ตัวเลือกตรงกับตาราง และยืนยัน /api/me เปิด import แล้ว ไม่ได้สร้างหรือแก้สินค้าในร้านผู้ใช้ระหว่างตรวจ

Migration 0002 เพิ่มคอลัมน์เท่านั้น Cloudflare deploy command เดิมจะ apply ก่อน deploy; ต้องใช้ทั้ง migration และ Worker เวอร์ชันใหม่ร่วมกัน

## วิดีโอที่ร้านเพิ่มเอง

รายละเอียดสินค้า → วางเคอร์เซอร์ → แทรกวิดีโอ → วางลิงก์ YouTube หรืออัปโหลด MP4 → บันทึกสินค้า

- YouTube รองรับ watch/share/Shorts/live URL แปลงเป็น youtube-nocookie embed ไม่มี autoplay ต้องเป็นคลิปที่เจ้าของอนุญาตให้ฝัง
- MP4 สูงสุด 20 MB/ไฟล์ ใช้โควตาร่วมรูป 500 MB/บัญชี แนะนำ H.264/AAC ไม่มี transcoding จึงขึ้นกับ codec ที่เบราว์เซอร์รองรับ
- ตรวจชนิด container จาก file signature ไม่เชื่อ file extension หรือ Content-Type อย่างเดียว ไม่ใช่การตรวจ codec/ความสมบูรณ์ของไฟล์ทั้งหมด
- วิดีโอฉบับร่างต้องผ่าน session เจ้าของ; สาธารณะเฉพาะเมื่ออยู่ในสินค้าที่เผยแพร่และร้านเปิด รองรับ HEAD และ single byte Range
- ลบวิดีโอใน editor คือเลิกแสดงหลังบันทึก ยังไม่ลบไฟล์ถาวรจาก R2 เช่นเดียวกับรูป
- ไม่เพิ่ม migration/resource/DNS ใหม่ ใช้ MEDIA binding ของโครงการเดิม
- Tests ตรวจ sanitizer/URL allowlist, upload limits, quota, tenant isolation, publication, SSR และ range responses
